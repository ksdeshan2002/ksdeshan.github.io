Project Overview

The Medical Store Management System (MSMS) is a complete web application designed to digitise and streamline the operations of a retail pharmaceutical store. It replaces manual paper-based processes with a real-time digital system accessible from any browser on the local network.

The application was designed following REST API principles, with a clear separation between the backend service layer and the frontend presentation layer — allowing either component to be upgraded independently.

Features

Inventory Management

  • Add, edit, and delete medicine records with expiry date tracking.
  • Automatic low-stock alerts when quantity falls below a configurable threshold.
  • Batch import of inventory via CSV upload.
  • Search and filter by name, category, manufacturer, or expiry status.

Billing and Sales

  • Point-of-sale billing interface with item search and barcode lookup.
  • Automatic stock deduction on bill confirmation.
  • PDF bill generation with itemised totals, tax, and discount.
  • Customer purchase history tracking.

Supplier Management

  • Supplier contact database with purchase order history.
  • Create and track purchase orders sent to suppliers.
  • Receive stock and automatically update inventory on delivery confirmation.

Reporting

  • Daily, weekly, and monthly sales summary reports.
  • Expiry report — medicines expiring within 30 / 60 / 90 days.
  • Stock value report — total inventory value at current purchase price.
  • Top-selling medicines ranking.

User Management

  • Role-based access control (Admin, Pharmacist, Cashier).
  • JWT-based authentication with session expiry.
  • Audit log of all user actions for compliance.

System Architecture

The application follows a standard three-tier web architecture:

  • Presentation Tier: React SPA served from a Node.js dev server (or static hosting in production), communicating with the backend exclusively via REST API calls.
  • Application Tier: Spring Boot RESTful service providing all business logic, validation, and data access through JPA repositories.
  • Data Tier: MySQL relational database with a normalised schema, managed through Hibernate ORM.
Design Principle

The backend exposes no HTML — it is a pure JSON REST API. The frontend is a pure consumer of that API. This separation means the React frontend could be replaced with a mobile app without any backend changes.

Database Design

The MySQL schema follows third normal form (3NF). Key entities and their relationships are:

Table Description Key Relations
medicines Master medicine catalogue with stock quantity FK to categories, suppliers
categories Medicine classification categories Parent of medicines
suppliers Supplier contact information Parent of medicines, purchase_orders
bills Sales bills header (customer, date, total) Parent of bill_items
bill_items Individual line items within a bill FK to bills, medicines
purchase_orders Orders placed to suppliers FK to suppliers
users System users with role assignments FK to roles

Lessons Learned

  • DTO pattern is essential: Exposing JPA entities directly in REST responses caused circular serialisation issues and leaked sensitive fields. DTOs solved both problems cleanly.
  • Global exception handling pays off: A single @ControllerAdvice class handling all exceptions returned consistent, structured error responses across the entire API — making frontend error handling predictable.
  • React Query simplifies state management: Using React Query for server state eliminated the need for Redux and significantly reduced the amount of boilerplate code in the frontend.
  • Database transactions: The bill creation process required an atomic transaction spanning multiple tables. Spring's @Transactional annotation handled this cleanly, but required careful understanding of transaction isolation levels to prevent race conditions.

Future Improvements

  • Add barcode scanning support using a USB barcode reader and Web Serial API integration in the browser frontend.
  • Implement real-time notifications using WebSockets (Spring WebFlux) for low-stock alerts visible to all logged-in users simultaneously.
  • Dockerise the application with a multi-stage Docker build and Docker Compose for the Spring Boot + MySQL stack.
  • Add a Progressive Web App (PWA) manifest and service worker for offline bill viewing on mobile devices.
  • Integrate a drug interaction checker API for pharmacist safety alerts at point of sale.
